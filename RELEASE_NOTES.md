# Release notes

*Notes de version en français plus bas.*

## 0.7.1 — 2026-10-15

Fixes found by an independent review (Codex) of 0.7.0:

- **Restore and remote access**: after a restore, remote access follows the restored settings and key; it was left running with the previous key, even when the backup had it turned off.
- **Restore safety**: if the current data cannot be fully copied to the “avant-restauration-…” folder, nothing is restored (a copy error used to be ignored).
- **Encryption of restore copies**: “avant-restauration-…” folders are now encrypted and decrypted with the rest of the data; they could stay unencrypted, or become unreadable once encryption was turned off.
- **Source checking**: the whole text attached to a citation is checked; a wrong figure placed after the first 600 characters of a long block under a source was missed.
- **Project page**: “See the N conversations” lists the project's conversations (it opened an empty search).
- Documentation: backup scope (models and the Skills folder are not included), limits of the accessibility checks, definition of the “expected page cited” measure; raw measurement data in `docs/mesures/`.

## 0.7.0 — 2026-10-15

- **Common search** (⌘K / Ctrl+K): one search across conversations, project notes and the text of project documents, without regard to accents; filter by project (or no project) and by type. Each result opens at its place: the message in its conversation, the note in its project, the document page in a reader with the words highlighted (previous and next page). Documents can also be read from the project page (“Read”).
- **Project page**: at the top, the next step you write down, the project's conversations, kept results and latest documents; “Search this project”. Deleting the project moves to an “Actions” menu; name and description to a folded section at the bottom. In a conversation linked to a project, the settings panel lists its documents (readable) and gives the number of notes.
- **Reviewed project memory**: “＋ Project memory” opens a review window (text can be corrected) before saving; each note keeps its source (conversation, question, model, date) and can reopen the conversation. Decisions and definitions you write in a project conversation (“we keep…”, “decision: …”) are offered as notes: save, correct or ignore; nothing is saved without your consent.
- **Automations** (new page): a routine watches a project; each document added is read, summarised with its sources by the chosen model, its citations checked, then offered for review (mark as reviewed, add to the project memory after review, run again). Run queue with the real step shown, stop and pause; a conversation, a benchmark series or a file plan comes first and the routine resumes afterwards; a run interrupted by closing Localia resumes at the next start. Routines only run while Localia is open.
- **Home (advanced mode) reorganised**: actions, Resume (last conversation, active projects with their next step), To do (results to review, errors, new watch articles, missed scheduled start: recorded events only), Activity (running and planned jobs), folded technical status.
- **Scheduled benchmark series kept**: after Localia closes, a future start is rescheduled; a past one is reported as missed on the home page, never started behind your back.
- **Encrypted backup and restore** (Privacy and security): all Localia data (except models and the Skills folder) in one `.localia` file, compressed and encrypted with a passphrase (AES-256-GCM, scrypt), independent of the system keychain, so it can be restored on another computer. Each item carries a SHA-256 fingerprint checked when reading; the backup is read back right after writing; “Check a backup” verifies passphrase and integrity without changing anything. Restoring copies the current data to an “avant-restauration-…” folder first, and re-encrypts with this computer's key when encryption is on.
- **Sources used, clearer and more reliable**: each cited source says what was found in the cited passage (figures, keywords, or only the document), with a note that a text match does not prove the statement correct. The checker now handles the ways models actually cite: a reference alone on its line (“This information comes from [doc — page 4]”), the source announced before the content (“According to [doc — page 2], …”, a heading followed by a list) and a citation used as a section heading; list lines under an announced source no longer count as figures without source. On 101 citations measured with qwen3:8b, false “not found” alerts went from 13 to 0; a false statement is still flagged in each layout covered by the tests.
- **Project documents**: when no extract chosen contains a word of the question, the model is told so and you see a warning; the pages sent are listed. The passage selection method was measured against BM25, a hybrid and semantic search (bge-m3) on the benchmark bank, with real answers from qwen3:8b: no clear gain, so the current method is kept (`docs/MESURE-RECHERCHE.md`, script `scripts/mesure-recherche.cjs`).
- **Real step while waiting for an answer**: reading the documents, loading the model into memory, generation.
- **Navigation**: Workspace (Home, Search, Projects, Conversations, Automations), Tools (Benchmark first, Model library, Bibliography, Files, Skills), Settings; simple mode keeps the same landmarks. Answer settings explain the difference between task, skill and path.
- **Accessibility checked in the app** (`scripts/audit-accessibilite.cjs`, `docs/ACCESSIBILITE.md`): 14 screens in light, dark, high-contrast, 200 % zoom and large text in a narrow window: contrast, horizontal scrolling, accessible names, 24 px targets, keyboard (every entry reached, focus visible and not hidden). Fixed: 46 controls too small, two low-contrast elements, overflows at 200 % zoom. Not a conformance claim: no screen-reader test yet.
- **English interface** completed (Benchmark results, comparison, security, PC analysis, model library, project pages); English README with English screenshots.
- Ollama embedding models (BERT families, “embed”) are no longer offered: they cannot chat.

Choose the project directly in the input box, or “Ask a question about this project”. The model knows your projects and explains how to link one.

- **Graphics card setting** for the built-in engine (Automatic / Always / Never), with the card actually used shown in “Analyse your PC”.
- **Offline model install**: from a file (USB stick), with SHA-256 check, and copy to a stick.

- **Accessibility**: text size, high contrast (also follows the system setting).
- **Two more engines**: Foundry Local (Microsoft, Windows) and Apple Intelligence (macOS 26).
- **Field instructions** (Health, Legal, Finance, Administration): general questions answered, caution kept; no invented anonymisation labels.
- **Benchmark**: series per field (Research, Coding, Telecoms, Cybersecurity…), model ranking per field.
- Fixes: an empty answer (whole length spent thinking) is now explained instead of silently dropped; input box layout in simple mode.

## 0.5.0 — 2026-10-05

- **Automatic checks, without any model**, under every answer (chat and comparison): calculations written in the answer are recomputed (e.g. “41.4 × 1000 × 0.30 = 12.42” flagged, exact 12,420); impossible page or excerpt references; quotations not found word for word in the document; numbers absent from the document. On the author's own series, every flagged answer had also been judged erroneous by the graders, with no false alarm.
- **Research assistant, task menu**: choosing a task (extract from a document, review an article, summarize, calculate, write or translate, code, general question) selects the model recommended by your Benchmark (most accurate, then least inventive, then fastest; repeated questions counted once), explains why, and adds a task instruction. A decision table “Which model for which task?” is added to the Benchmark.
- **Project memory**: projects hold your notes (sources, decisions, definitions, results); in a conversation linked to a project, the notes are sent to the model as context (all of them up to 6,000 characters, otherwise those closest to the question), and Localia shows which notes were sent. Only what you write, or an answer you explicitly add, enters the memory.
- **Bibliography tab**: author citations in an article (“Barbedo [24] reviewed…”) are checked offline against the numbered reference list (on the author's published article: 35 references, 12 author citations, one real mismatch found, no false alarm). Optional and **off by default**: checking that references exist (Crossref) and searching for articles (OpenAlex), with “copy reference” and “add to project”. Only the reference text or the query is sent, only to these two services; on the same article, 24 of 35 references were matched, 9 flagged for a manual check, 2 not found (preprints).
- **Files tab, actions with your consent**: describe what you want done in a folder (sort, rename, create folders or a note); the model proposes a plan, Localia checks every action against the real folder, and nothing changes until you tick and apply the actions. Safeguards: only folders you authorize through the system dialog (never the whole home folder, system or settings folders); the model sees file names, types and sizes, never their contents; nothing is overwritten or permanently deleted (removed items go to the Trash); every operation is logged and can be undone. A benchmark series (`serie-actions.txt`, 10 questions) measures how reliable each model is at this task, with automatic detection of impossible actions.
- **Optional encryption of your data** (Model settings → Data on this Mac): conversations, comparisons, projects, extracted PDF text, settings and the action log are encrypted with AES-256-GCM; the random key is protected by the macOS Keychain, with an exportable recovery key. Existing files are converted in place and remain readable during the conversion; if the key is unavailable, nothing is loaded or overwritten until the recovery key is imported. The FileVault status is shown.
- **Zotero, read-only and local** (Bibliography tab): search your Zotero library, compare an article's references with it, open an item in Zotero, or start a conversation on an item's PDF. Uses Zotero's local API (127.0.0.1); nothing leaves the Mac. Reference matching now requires a matching author or year when titles only partly overlap, and whole-word author names (“Li” no longer matches “Liu”).
- **Literature watch** (Bibliography tab): follow topics daily or weekly; while Localia is open and online search is allowed, new articles are fetched from OpenAlex (recent articles, by relevance, without duplicates), announced by a notification and a count on the tab, and can be added to Zotero, to a project, or marked as seen.
- **Scheduled benchmark series**: choose a start time in Comparison; the Mac is kept awake while waiting and during every series (no more `caffeinate`).
- **Apple Silicon and Windows**: Ollama is found in its usual places on each system (or `OLLAMA_PATH`); system information, disk-encryption status, forbidden folders and messages adapt to the system; Mac builds are signed ad hoc (required on Apple Silicon); Windows installer and .zip. Tests and builds run on macOS Apple Silicon, macOS Intel and Windows in the GitHub workflow.
- **Integrated engine by default (step 3)**: the getting-started guide downloads the catalogue model recommended for the computer's memory with the integrated engine; Ollama becomes optional (used if present, its compatible models reusable). The model library shows Hugging Face first. A real-engine test (SmolLM2 135M, 105 MB) runs in the built application on every system in the GitHub workflow.
- **Integrated engine, step 2: models from Hugging Face** (Model library): a catalogue of 10 freely accessible GGUF models (Gemma 4 E2B/E4B/12B, Gemma 3 1B/4B/12B, Qwen 3 4B/8B, Qwen 3.5 4B/9B, Q4_K_M), each with its licence and a verdict for the computer's memory, or any GGUF file by its Hugging Face address (gated repositories refused). Downloads resume after a cut or a pause, the SHA-256 fingerprint is checked before use, free disk space is checked first, the model is test-loaded before being added; a file already downloaded by Ollama with the same fingerprint is reused without downloading.
- **Integrated engine (llama.cpp), step 1**: Localia can run GGUF models itself, without Ollama, in a separate process (a crashing model does not close Localia). Models already downloaded by Ollama are reused without a new download when their file is standard (all Qwen 3 / 3.5 models tested); files converted by Ollama in its own format (Gemma 3) are detected and refused with an explanation. Integrated-engine models appear as `integre/…` next to Ollama's, with the same settings, checks, measurements and benchmark (the engine is recorded with each answer). Ships the CPU, Metal and Vulkan engines (CUDA left out for size).
- **Use Localia from your phone or another computer** (Settings → Access from your other devices, off by default): scan the QR code (local network, or Tailscale from outside) and ask questions from a mobile page; the models run on the computer, questions go through the Localia window (same conversations, skills, checks), answers arrive as they are written. Secret key, repeated wrong keys blocked, foreign Host headers refused, connected devices listed, key can be changed at any time.
- **Read a web page**: “＋ Add → Web page” (or `/web address`) turns a page into the conversation's document, like a PDF: main text only (menus, scripts and footers removed, nothing executed), split into numbered sections, with the usual checks (quotes, numbers, hidden instructions). Links to PDFs are read as PDFs. Private and local network addresses are refused, after every redirect; 5 MB at most.
- **“Your PC’s performance” tab**: processor, memory, graphics cards (macOS: system_profiler; Windows: nvidia-smi and WMI), disk and Ollama status; whether Ollama can use the GPU (Apple chip, NVIDIA, recent AMD; never on Intel Macs); a verdict for each installed or suggested model (comfortable, memory tight, too big) and its response speed, from the benchmark or a one-minute test (short answer, model unloaded afterwards, never during a series).
- **Getting-started guide**, opened at first launch while no model is installed (and from the sidebar): installs or starts Ollama, recommends a model for the computer's memory (Gemma 3 1B/4B/12B, Qwen 3 8B, sizes checked against the Ollama catalogue) with a free-disk check, downloads it, and proposes a first question. The model library's starter card follows the same recommendation. One “＋ Add” button attaches a PDF, instructions, code or data.
- **Skills** (new tab): reusable instructions written as Markdown files in `Documents/Localia/Compétences` (edit, add, share). A skill is chosen in the Task menu or called at the start of a message (`/data-missing …`, suggestions while typing, `/competences` for the list); it can be linked to a task type (base instruction and benchmark-recommended model), attach reference files, or chain other skills as a step-by-step path. 42 starter skills in French: raw data (9 steps), NASA POWER weather data, designing a thesis or article project, linking thesis and articles, writing an article (9 steps, IEEE review, reply to reviewers), writing a thesis (7 steps), developing an application (9 steps).
- **Text, code and data files in conversations** (“＋ File”): instructions (.txt, .md), code (.py, .R, .sql…) and data tables (.csv, .tsv). A table is never sent in full: the model receives a profile (columns, types, missing and -999 values, min/max, date range, duplicates, first and last rows, NASA POWER header and the exact date conversion), so the code it writes uses the real column names. New task “Prepare and analyse data (Python)”. Search results: duplicates removed, document type shown, “Add to Zotero”.
- **Prompt-injection detection** when a PDF is imported (sentences addressed to an AI, e.g. “ignore all previous instructions”).
- Benchmark: table of automatic alerts per model; alert counts in the raw data export.
- Long documents: no more 5-minute timeout while Ollama reads the document; clearer connection error messages.
- Comparison: answers show each grader's verdict, invention flag, score and comment; grader comparison charts in the Benchmark.

Corrections issues d’une relecture indépendante (Codex) de la 0.7.0 :

## 0.7.0 — 15 octobre 2026

- **Recherche commune** (⌘K / Ctrl+K) : une seule recherche dans les conversations, les notes des projets et le texte de leurs documents, sans tenir compte des accents ; filtres par projet (ou sans projet) et par type. Chaque résultat s’ouvre à son endroit : le message dans sa conversation, la note dans son projet, la page du document dans un lecteur, mots surlignés (page précédente et suivante). La suppression passe dans un menu « Actions », le nom et la description dans une section repliée en bas. Dans une conversation reliée à un projet, le panneau des réglages liste ses documents (lisibles) et indique le nombre de notes.
- **Mémoire du projet relue** : « ＋ Mémoire du projet » ouvre une fenêtre de relecture (texte corrigeable) avant l’enregistrement ; chaque note garde sa provenance (conversation, question, modèle, date) et rouvre la conversation. Les décisions et définitions que vous écrivez dans une conversation de projet (« on retient… », « décision : … ») sont proposées comme notes : enregistrer, corriger ou ignorer ; rien n’est enregistré sans votre accord.
- **Automatisations** (nouvelle page) : une routine surveille un projet ; chaque document ajouté est lu, résumé avec ses sources par le modèle choisi, ses citations vérifiées, puis proposé à la relecture (marquer comme relu, ajouter à la mémoire du projet après relecture, relancer). File d’exécution avec l’étape réelle, arrêt et suspension ; une conversation, une série du Benchmark ou un plan de fichiers passe avant et la routine reprend ensuite ; une exécution interrompue par la fermeture de Localia reprend au démarrage suivant. Les routines ne tournent que lorsque Localia est ouverte.
- **Accueil du mode avancé réorganisé** : actions, Reprendre (dernière conversation, projets actifs et leur prochaine étape), À traiter (résultats à relire, erreurs, nouveaux articles de la veille, départ programmé manqué : seulement des événements enregistrés), Activité (traitements en cours et prévus), état technique replié.
- **Départ programmé du Benchmark conservé** : après une fermeture de Localia, un départ à venir est reprogrammé ; un départ passé est signalé comme manqué sur l’accueil, jamais lancé à votre insu.
- **Sauvegarde chiffrée et restauration** (Confidentialité et sécurité) : toutes les données de Localia (hors modèles et dossier Compétences) dans un seul fichier `.localia`, compressé et chiffré par une phrase de passe (AES-256-GCM, scrypt), indépendant du trousseau : il se restaure aussi sur un autre ordinateur. Chaque élément porte une empreinte SHA-256 vérifiée à la lecture ; la sauvegarde est relue juste après son écriture ; « Vérifier une sauvegarde » contrôle phrase de passe et intégrité sans rien changer. La restauration copie d’abord les données actuelles dans un dossier « avant-restauration-… », et rechiffre avec la clé de l’ordinateur si le chiffrement est actif.
- **Sources utilisées, plus claires et plus fiables** : chaque source citée dit ce qui a été retrouvé dans le passage cité (chiffres, mots-clés, ou seulement le document), avec la mention qu’une correspondance de texte ne prouve pas la justesse de l’affirmation. La vérification suit désormais les façons réelles de citer des modèles : renvoi seul sur sa ligne (« Ces informations sont tirées de [doc — page 4] »), source annoncée avant le contenu (« Selon le document [doc — page 2], … », titre suivi d’une liste), citation en titre de section ; les lignes d’une liste sous une source annoncée ne comptent plus comme chiffres sans source. Sur 101 citations mesurées avec qwen3:8b, les fausses alertes « non retrouvée » passent de 13 à 0 ; une affirmation fausse reste signalée dans chaque disposition couverte par les tests.
- **Documents des projets** : quand aucun extrait choisi ne contient de mot de la question, le modèle en est averti et vous voyez un avertissement ; les pages transmises sont indiquées. La méthode de choix des passages a été mesurée contre BM25, un hybride et la recherche sémantique (bge-m3) sur la banque du Benchmark, avec de vraies réponses de qwen3:8b : aucun gain net, la méthode actuelle est conservée (`docs/MESURE-RECHERCHE.md`, script `scripts/mesure-recherche.cjs`).
- **Étape réelle pendant l’attente d’une réponse** : lecture des documents, chargement du modèle en mémoire, génération.
- **Navigation** : Espace de travail (Accueil, Rechercher, Projets, Conversations, Automatisations), Outils (Benchmark en premier, Bibliothèque de modèles, Bibliographie, Fichiers, Compétences), Réglages ; le mode simple garde les mêmes repères. Les réglages de la réponse expliquent la différence entre tâche, compétence et parcours.
- **Accessibilité vérifiée dans l’application** (`scripts/audit-accessibilite.cjs`, `docs/ACCESSIBILITE.md`) : 14 écrans en thème clair, sombre, contraste renforcé, zoom à 200 % et texte très grand en fenêtre étroite : contrastes, défilement horizontal, noms accessibles, cibles de 24 px, clavier (chaque entrée atteinte, focus visible et non masqué). Corrigés : 46 commandes trop petites, deux éléments peu contrastés, débordements au zoom de 200 %. Pas une déclaration de conformité : aucun essai au lecteur d’écran pour l’instant.
- **Interface en anglais** complétée (résultats du Benchmark, comparaison, sécurité, analyse du PC, bibliothèque de modèles, pages des projets) ; README anglais avec captures en anglais.
- Les modèles d’embeddings d’Ollama (familles BERT, « embed ») ne sont plus proposés : ils ne savent pas converser.

## 0.5.0 — 5 octobre 2026

- **Vérifications automatiques, sans modèle**, sous chaque réponse (conversation et comparaison) : calculs écrits dans la réponse refaits (par exemple « 41,4 × 1000 × 0,30 = 12,42 » signalé, résultat exact 12 420) ; références de pages ou d'extraits impossibles ; citations introuvables mot pour mot dans le document ; nombres absents du document. Sur les séries de l'auteur, chaque réponse signalée avait aussi été jugée erronée par les correcteurs, sans fausse alerte.
- **Assistant de recherche, menu Tâche** : choisir une tâche (extraire d'un document, relire un article, résumer, calculer, rédiger ou traduire, coder, question générale) sélectionne le modèle conseillé par votre Benchmark (le plus précis, puis le moins inventif, puis le plus rapide ; une question répétée compte une fois), explique ce choix et ajoute une consigne adaptée. Tableau de décision « Quel modèle pour quelle tâche ? » dans le Benchmark.
- **Mémoire par projet** : chaque projet garde vos notes (sources, décisions, définitions, résultats) ; dans une conversation liée à un projet, elles sont envoyées au modèle comme contexte (toutes jusqu'à 6 000 caractères, sinon les plus proches de la question), et Localia indique lesquelles. Seul ce que vous écrivez, ou une réponse que vous ajoutez vous-même, entre dans la mémoire.
- **Onglet Bibliographie** : les citations d'auteurs d'un article (« Barbedo [24] reviewed… ») sont comparées hors ligne à la liste de références numérotées (sur l'article publié de l'auteur : 35 références, 12 citations d'auteurs, une erreur réelle trouvée, aucune fausse alerte). En option, **désactivées par défaut** : vérification de l'existence des références (Crossref) et recherche d'articles (OpenAlex), avec « Copier la référence » et « Ajouter au projet ». Seuls le texte de la référence ou la recherche sont envoyés, et uniquement à ces deux services ; sur le même article, 24 références sur 35 retrouvées, 9 à vérifier à la main, 2 introuvables (prépublications).
- **Onglet Fichiers, actions avec votre accord** : décrivez ce que vous voulez faire dans un dossier (classer, renommer, créer des dossiers ou une note) ; le modèle propose un plan, Localia vérifie chaque action sur le dossier réel, et rien n'est modifié avant que vous ne cochiez et appliquiez les actions. Garde-fous : uniquement les dossiers autorisés par la fenêtre du système (jamais le dossier personnel entier, ni les dossiers système ou de réglages) ; le modèle voit les noms, types et tailles des fichiers, jamais leur contenu ; rien n'est écrasé ni supprimé définitivement (ce qui est retiré va à la Corbeille) ; chaque opération est inscrite au journal et peut être annulée. Une série du Benchmark (`serie-actions.txt`, 10 questions) mesure la fiabilité de chaque modèle pour cette tâche, avec détection automatique des actions impossibles.
- **Chiffrement facultatif de vos données** (Réglages des modèles → Données sur ce Mac) : conversations, comparaisons, projets, textes extraits des PDF, réglages et journal des actions chiffrés en AES-256-GCM ; la clé aléatoire est protégée par le trousseau de macOS, avec une clé de secours exportable. Les fichiers existants sont convertis sur place et restent lisibles pendant la conversion ; si la clé est indisponible, rien n'est chargé ni écrasé tant que la clé de secours n'est pas importée. L'état de FileVault est affiché.
- **Zotero, en lecture seule et en local** (onglet Bibliographie) : recherche dans votre bibliothèque Zotero, comparaison des références d'un article avec elle, ouverture d'un élément dans Zotero, conversation sur le PDF d'un élément. Passe par l'API locale de Zotero (127.0.0.1) : rien ne sort du Mac. La comparaison des références exige désormais l'auteur ou l'année quand les titres ne se recoupent qu'en partie, et le nom d'auteur entier (« Li » ne correspond plus à « Liu »).
- **Veille bibliographique** (onglet Bibliographie) : sujets suivis chaque jour ou chaque semaine ; tant que Localia est ouverte et la recherche en ligne autorisée, les nouveaux articles sont cherchés sur OpenAlex (articles récents, par pertinence, sans doublon), signalés par une notification et un compteur sur l'onglet, et peuvent être ajoutés à Zotero, à un projet, ou marqués comme vus.
- **Séries du Benchmark programmées** : une heure de départ dans Comparaison ; le Mac reste éveillé pendant l'attente et pendant toute série (plus besoin de `caffeinate`).
- **Apple Silicon et Windows** : Ollama est cherché à ses emplacements habituels sur chaque système (ou `OLLAMA_PATH`) ; informations système, état du chiffrement du disque, dossiers interdits et messages s'adaptent au système ; versions Mac signées ad hoc (obligatoire sur Apple Silicon) ; installateur et .zip pour Windows. Tests et constructions sur macOS Apple Silicon, macOS Intel et Windows dans le workflow GitHub.
- **Moteur intégré par défaut (étape 3)** : le guide de démarrage télécharge, avec le moteur intégré, le modèle du catalogue conseillé pour la mémoire de l'ordinateur ; Ollama devient facultatif (utilisé s'il est présent, ses modèles compatibles réutilisables). La Bibliothèque présente Hugging Face en premier. Un test du moteur réel (SmolLM2 135M, 105 Mo) tourne dans l'application construite sur chaque système dans le workflow GitHub.
- **Moteur intégré, étape 2 : modèles depuis Hugging Face** (Bibliothèque de modèles) : catalogue de 10 modèles GGUF en accès libre (Gemma 4 E2B/E4B/12B, Gemma 3 1B/4B/12B, Qwen 3 4B/8B, Qwen 3.5 4B/9B, Q4_K_M), chacun avec sa licence et un verdict pour la mémoire de l'ordinateur, ou tout fichier GGUF par son adresse Hugging Face (dépôts à accès restreint refusés). Le téléchargement reprend après une coupure ou une pause, l'empreinte SHA-256 est vérifiée avant usage, la place libre est contrôlée avant, le modèle est essayé avant d'être ajouté ; un fichier déjà téléchargé par Ollama avec la même empreinte est réutilisé sans téléchargement.
- **Moteur intégré (llama.cpp), étape 1** : Localia peut faire tourner elle-même des modèles GGUF, sans Ollama, dans un processus séparé (un modèle qui plante ne ferme pas Localia). Les modèles déjà téléchargés par Ollama sont repris sans nouveau téléchargement quand leur fichier est standard (tous les Qwen 3 et 3.5 essayés) ; les fichiers convertis par Ollama dans son propre format (Gemma 3) sont repérés et refusés avec une explication. Les modèles du moteur intégré apparaissent sous la forme `integre/…` à côté de ceux d'Ollama, avec les mêmes réglages, vérifications, mesures et Benchmark (le moteur est enregistré avec chaque réponse). Moteurs fournis : processeur, Metal et Vulkan (CUDA écarté pour la taille).
- **Utiliser Localia depuis votre téléphone ou un autre ordinateur** (Réglages → Accès depuis vos autres appareils, désactivé par défaut) : scannez le QR code (réseau local, ou Tailscale depuis l'extérieur) et posez vos questions depuis une page adaptée au téléphone ; les modèles tournent sur l'ordinateur, les questions passent par la fenêtre de Localia (mêmes conversations, compétences, vérifications), les réponses arrivent au fil de l'écriture. Clé secrète, essais répétés bloqués, en-têtes Host étrangers refusés, appareils connectés affichés, clé changeable à tout moment.
- **Lire une page web** : une adresse https collée dans le message (ou `/web adresse`) fait d'une page le document de la conversation, comme un PDF : texte principal seulement (menus, scripts et pieds de page retirés, rien n'est exécuté), découpé en sections numérotées, avec les vérifications habituelles (citations, chiffres, consignes piégées). Un lien vers un PDF est lu comme un PDF. Adresses privées et du réseau local refusées, après chaque redirection ; 5 Mo au plus.
- **Onglet « Performances de votre PC »** : processeur, mémoire, cartes graphiques (macOS : system_profiler ; Windows : nvidia-smi et WMI), disque et état d'Ollama ; Ollama peut-il utiliser la carte graphique (puce Apple, NVIDIA, AMD récente ; jamais sur un Mac Intel) ; verdict pour chaque modèle installé ou conseillé (confortable, mémoire juste, trop gros) et vitesse de réponse, d'après le Benchmark ou un test d'une minute (réponse courte, modèle déchargé ensuite, jamais pendant une série).
- **Guide de démarrage**, ouvert au premier lancement tant qu'aucun modèle n'est installé (et depuis la colonne de gauche) : installe ou démarre Ollama, conseille un modèle selon la mémoire de l'ordinateur (Gemma 3 1B/4B/12B, Qwen 3 8B, tailles vérifiées dans le catalogue d'Ollama) en vérifiant la place libre, le télécharge et propose une première question. La carte « Pour commencer » de la Bibliothèque suit le même conseil. Le trombone (ou un fichier glissé dans la fenêtre) joint un PDF, des consignes, du code ou des données.
- **Compétences** (nouvel onglet) : consignes réutilisables écrites en fichiers Markdown dans `Documents/Localia/Compétences` (à modifier, compléter, partager). Une compétence se choisit dans le menu Tâche ou s'appelle en début de message (`/donnees-manquants …`, suggestions pendant la saisie, `/competences` pour la liste) ; elle peut être liée à un type de tâche (consigne de base et modèle conseillé par le Benchmark), joindre des fichiers de référence, ou enchaîner d'autres compétences en parcours. 42 compétences de départ : données brutes (9 étapes), météo NASA POWER, concevoir un projet de thèse ou d'article, relier thèse et articles, rédiger un article (9 étapes, relecture IEEE, réponse aux relecteurs), rédiger une thèse (7 étapes), développer une application (9 étapes).
- **Fichiers texte, code et données dans les conversations** (« ＋ Fichier ») : consignes (.txt, .md), code (.py, .R, .sql…) et tableaux de données (.csv, .tsv). Un tableau n'est jamais envoyé en entier : le modèle reçoit son portrait (colonnes, types, valeurs manquantes et -999, minimum et maximum, période, doublons, premières et dernières lignes, en-tête NASA POWER et conversion exacte des dates), pour écrire du code avec les vrais noms de colonnes. Nouvelle tâche « Préparer et analyser des données (Python) ». Recherche d'articles : doublons écartés, type de document affiché, « Ajouter à Zotero ».
- **Détection des consignes piégées** à l'import d'un PDF (phrases adressées à une IA, par exemple « ignore all previous instructions »).
- Benchmark : tableau des alertes automatiques par modèle ; comptes d'alertes dans l'export des données brutes.
- Documents longs : plus de coupure au bout de 5 minutes pendant qu'Ollama lit le document ; messages d'erreur de connexion plus précis.
- Comparaison : chaque réponse affiche le verdict, l'invention, la note et le commentaire de chaque correcteur ; graphiques de comparaison des correcteurs dans le Benchmark.
